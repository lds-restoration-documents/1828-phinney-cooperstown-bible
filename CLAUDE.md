# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A text corpus, not software: AI-assisted transcriptions of the 1828 H. & E. Phinney (Cooperstown) King James Bible, extracted from a scan on Archive.org of a Brigham Young University Library copy. It is the same edition Joseph Smith used for his Bible revision, but not his copy. There is no build, lint, or test tooling. The scan PDF itself is **not** in this repo; the scripts that produce the derived files are in `tools/`.

## How the files relate

`phinney-bible-pages/page-001.md` … `page-884.md` are the **source of truth**: one file per PDF page, named by *PDF page number*, not the printed folio. Everything else is derived from them:

- `phinney-bible.md`: all pages, main text only, joined into one file.
- `phinney-bible.txt`: the same, with all Markdown removed.
- `phinney-bible-sparse.txt`: biblical text only (books, chapters, verses, incl. the Apocrypha), no tables, intro material, contents or chapter summaries.
- `transcription-notes.md`: method, conventions, residual-risk notes, and a per-page log of every `uncertain` / `[illegible]` / layout comment.

The derived files are generated by the scripts in `tools/`, and a fix made only in a derived file is lost on the next regeneration. After changing any page file, rebuild them (Python 3 standard library only, run from anywhere):

```
python3 tools/compile_markdown.py   # phinney-bible.md
python3 tools/make_plaintext.py     # phinney-bible.txt
python3 tools/make_sparse.py        # phinney-bible-sparse.txt
```

Run on unchanged page files these reproduce the committed outputs byte for byte, so a clean `git diff` on the three combined files after a rebuild means nothing else moved. `tools/render_pages.py` (needs `pypdfium2`) renders scan pages into the crops used for transcription; `tools/transcription-spec.md` and `tools/audit-spec.md` are the instructions the transcribing and auditing agents followed. `transcription-notes.md` §7 describes what the generator strips and joins.

## Page file format

Each page file starts `<!-- PDF page NNN -->`, then: an optional `**Header:**` running-head line (parts separated by ` | `), headings (`#` book title, `## CHAPTER X.`), a chapter summary as plain text, one paragraph per verse with the verse number first, then after a `---` rule a `### Marginal notes` section and a `Footer:` line. Blank pages, covers and stamps are a one-line comment. See `transcription-notes.md` §2 for the full conventions (superscript reference letters as `<sup>`, `*italic*` for the translators' supplied words, how multi-column layouts are ordered).

## Rules when editing

- **Write what the scan shows, never what you think it should say.** Printer's errors, odd spellings, wrong verse numbers, odd dates and "impossible" cross-references are kept as printed (e.g. Ex. 30:8 is numbered "o" on p. 72, Gen. 4:2 has no verse number, Num. 1:32 is numbered "23", 2 Sam. "38, 12" on p. 95). Do not "fix" them from knowledge of the KJV.
- Doubtful readings stay in place with `<!-- uncertain: … -->`; unreadable text is `[illegible]`. Only change a marginal digit when you can read it clearly at zoom; 3/5/8/9 are often indistinguishable even at 600 dpi.
- The marginal cross-reference print is the weak point; the verse text is reliable.
- Confidence differs by page range. PDF pages 1–329 (except 213, 214, 230, 246, 274–278, 290–294, 308–310, 324–326) were written by Opus 5.5 and later audited against the scan. Everything else was written by Sonnet 5.5 under the "write what the scan shows" rule and has **not** been audited. No page has been proofread by a person.
- Chapter summaries and running-head punctuation are kept as printed even when they look wrong (e.g. p. 324 summary starts "17").
- Verified checks that held at last run: 884 page files, no duplicate content, every file's first-line page comment matches its filename, balanced `<!-- -->` and `<sup>` tags.
